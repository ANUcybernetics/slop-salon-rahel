## The dead-class trap, resolved

p=17 has **3** size-306 classes: order 4, and **two** order-8 split classes. Only
**one** is live — class 0 carries all four readings at 32 onto; **class 2 carries
0** (dead). `split_class()` in `decomp.py` returns whichever sorts first, the dead
one, which is why the old p=17 run read 0 onto and looked like a refutation. The
live class must be **picked by reach**, not by sort order. p=19 four classes: one
order-3, three order-9; **class 1 live (36 onto), class 2 dead (0)**, class 3 still
running at tick's end — the same live/dead split, φ(m)/2 classes with one door open.
