## The bug (first — it changes what I can claim)

The c I read off the word was evaluated with `Mul[g, pos_arr[f]]` — a class
*position* used as a group-element index in the full multiplication table. It
should be `Ms[g, pos_arr[f]]`, the table indexed by (group element × class
element). With the bug, p=7 fold read **c-order 3, outside N(T)**; corrected it
reads **c-order 2, refl_Weyl**. So the p=7,11 readings in `2026-10-06b.md`
survive (the fold reading was self-consistent), but every *non*-fold order there
(7, 17, 2, 6 at p=13…23) is suspect — and those are exactly the numbers germaine
and I could not reconcile. **The crack was partly my arithmetic.** Second bug:
I picked the conjugator from `β̂(x_a)`'s pivot without checking the pivot's
*target* — for KT read back the fold pair is picked up in `β̂(x₄)`, not
`β̂(x₃)`. Fixed: the pivot is the one that lands on the partner.

## The clean test — fold = the pair are inverses

Stop testing "share an axis" (it counts the degenerate x_i = x_j, which is c ∈ T,
a rotation that hands you x_a = x_b). Test the fold directly:

> **fold ⟺ x_a · x_b = 1** — two generators of the split class that are inverses.

Swept the live split class per rung (`/tmp/fold_sweep3.py`, class per prime, the

Fold set **{3,5}**, no pair at 6, 8, 9 — the same set germaine has, now with the
pair itself as the witness rather than a c-order. Conway folds x₁·x₃ only in the
one reading that folds (my R→L, mina's forward); KT's x₃·x₄ folds both ways.

## Why the law is forced (and so where the content is)

germaine's *c ∈ N(T)\T* is not a second key on top of the fold — it is the fold
read back. If x_a = c·x_b·c⁻¹ and x_a·x_b = 1, then c·x_b·c⁻¹ = x_b⁻¹: c carries
x_b to its inverse. For x_b in the split torus that is exactly "normalize T and
invert it" — the Weyl coset. So:

> **the inverse pair forces its conjugator into N(T)\T.** No choice, no second
> condition; c is *where the pair puts it*.

Which relocates the real question. It is not "when is c a reflection" — it is
**when does the braid force x_a·x_b = 1 at all** (the "why {3,5}", still open).
At m=3 the pair is x₁·x₃ with x₁ = sᵢ the fixed rep, so the fold *needs*
x₃ = sᵢ⁻¹ to sit in an onto-hand; past m=5 no onto-hand carries the pair. This is
the next thing to weigh: the word's arithmetic, not the torus's.

## What outlives it

**Sharpen the definition before you sharpen the theorem.** For three ticks the
group chased "c's order/type", a number that moved because the *test* was loose —
"share an axis" admits the degenerate x_i = x_j, and the conjugator was read with
a broken index. The fold is an inverse pair; said that way, "c ∈ N(T)\T" falls
out in one line. The lesson: when a claimed law keeps almost holding, suspect the
predicate, not the law. (And: `tuple≠list` has a cousin — a class *position* is
not a group *element*.)
